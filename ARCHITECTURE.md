# Architecture

PromptDock is three applications that talk to one another over three frozen wire
contracts, now held in one repository. Nothing runs inside anything else: each
piece can be swapped for an alternative implementation as long as it satisfies
the same contract.

```text
             ┌───────────────────┐
             │ PromptDock Desktop│
             │ Windows / Tauri   │
             └─────────┬─────────┘
                       │
                  HTTP / Contract
                       │
             ┌─────────▼─────────┐
             │ PromptDock Relay  │
             │ Rust              │
             └──────┬───────┬────┘
                    │       │
                WeChat    Admin API
                            │
                     ┌──────▼──────┐
                     │ Relay Admin │
                     │ Vue         │
                     └─────────────┘
```

This file states only what is stable: which component owns which kind of
decision, and which edges must never be short-circuited. The module-level view —
per-crate responsibilities, the directory map, request paths and the happy-path
sequence — lives in [docs/architecture/](docs/architecture/README.md).

## Relay — `apps/server` + `crates/`

Rust, Linux-first, one binary (`promptdock-relay`) built from the
`promptdock-server` crate over the `relay-*` crates.

Relay owns:

- communication between a desktop host and the outside world
- authentication, device records and scopes
- the durable notification queue, its delivery state and retention rules
- the WeChat provider (`crates/relay-provider-wechat`, `crates/wechat-ilink`)
- result publication: the read-only `result_pages_v1` documents
- the gateway transport (`crates/relay-transport-gateway`)
- the Admin API, and therefore the Admin `/v2` contract surface

Relay never:

- executes an Agent, or runs a user's build, test or shell command
- reaches into a workspace to read source
- reads or stores a local Codex credential
- installs or observes hooks

**Relay is an external communication node.** That is why queue, provider and
storage are separate crates rather than functions in one binary: no part of the
server has a path to a user's machine, and the crate boundaries are what keep
that true as the code grows.

## Desktop — `apps/desktop`

A Windows host (Tauri 2 with a Vue front-end) whose Rust crate deliberately sits
outside the Cargo workspace: it is Windows-only, on a different edition and
version line, and must not be able to move the relay's lockfile.

Desktop owns:

- local event capture, through the Codex Hooks already installed by the user
- local data and the capture policy that governs it
- local notification, attention and run-inbox state
- the Relay client, and the tray and result presentation

Desktop never owns:

- the server-side WeChat session
- the Admin API or operator lifecycle
- anything a user has not explicitly configured locally

**WeChat is server-owned.** The desktop host has no WeChat credentials and no
provider code; it hands events to Relay and reads back delivery state.

## Relay Admin — `apps/admin`

A Vue operator console that speaks only Admin `/v2`, shipped as a built static
bundle behind Caddy in the combined image. It is a client, not a privileged
process: it has no direct path to relay storage and no desktop-side state. Its
generated API types come from `packages/admin-api-contract`, never from
hand-written copies.

## Contracts — `contracts/`

| Contract | Directory | Producer | Consumers |
|---|---|---|---|
| HTTP `/v1` | `contracts/server-http/v1/` | relay | desktop host |
| Admin `/v2` | `contracts/admin-api/v2/` | relay | relay admin, operator tooling |
| Node link `/v5` | `contracts/node-link/v5/` | relay | gateway clients |

`contracts/` is the single canonical source for all three. A fixture exists once
and is referenced from both sides; copying a fixture into an application tree is
a defect, not a convenience.

`/v5` is retained as a compatibility surface from the project's history: the
fixtures and the relay-side tests are live, while the desktop host does not open
a `/v5` connection today. Treat it as a documented edge, not as dead code to
prune or a feature to build on implicitly.

## Generated artifacts

- `contracts/*/manifest.json` — SHA-256 over every fixture, regenerated by
  `scripts/contracts/*-contract-manifest.{sh,ps1}`
- `packages/admin-api-contract` — TypeScript types generated from the Admin
  OpenAPI surface by `scripts/contracts/generate-admin-api-contract.mjs`

Both are checked back in and verified in CI, so a consumer cannot silently drift
from a producer. Regenerate them; do not hand-edit them.

## Storage

- Relay: SQLite in WAL mode behind `crates/relay-storage-sqlite`, with the
  migration set it owns. No ORM, no external database service.
- Desktop: `%LOCALAPPDATA%\promptdock-desktop\` — a SQLite inbox plus
  DPAPI-encrypted JSONL capture, with a fixed reset allowlist. See
  [docs/desktop/local-data.md](docs/desktop/local-data.md).

Neither side stores a plaintext credential. Runtime databases, logs and
environment files are refused by the public-tree gate as a path pattern, so they
cannot be committed by accident.

## Extension points

Additional delivery providers, transports or result renderers are expected to
arrive as explicit adapters — a new `crates/relay-provider-*`, a new contract
version — rather than by widening an existing component's responsibilities. No
scaffolding for a future integration is checked in ahead of the integration
itself.
